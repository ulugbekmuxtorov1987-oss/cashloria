# Аудит Finly — отчёт (код не менялся)

Проверено: маршруты, ссылки, формы, auth, admin, Supabase/RLS/миграции, прогресс/XP/streak, уроки/квизы, симуляторы, i18n, SEO, a11y, производительность, безопасность. TypeScript-проверка проходит без ошибок, последний билд — OK. Ниже — найденные проблемы с подтверждением.

## Critical

1. **Аналитика прохождения уроков не пишется вообще** — `src/lib/analytics.ts:38` шлёт `event_type: "lesson_complete"`, а CHECK в БД (`supabase/migrations/2026081810...sql:206`) допускает только `page_view | lesson_completed | quiz_attempt`. Insert падает и глушится `catch {}` в `analytics.ts:22-31`. Подтверждено запросом к БД: 254 `page_view`, 3 `quiz_attempt`, **0** событий завершения. Админ-обзор (`_authenticated/admin.tsx:82,91`) фильтрует по тому же неверному значению → «Lessons completed» всегда 0.
   Фикс: привести код к `lesson_completed` (или расширить CHECK), и логировать ошибку insert в dev.

2. **Русский язык отсутствует полностью** — директории `src/lib/finly/content/ru` нет, `registerContentPack` не вызывается нигде (`content-i18n.ts:38` — единственное упоминание), а `learn.$lessonId.tsx` / `learn.index.tsx` / `dashboard.tsx` вообще не используют `localizeLesson/Level/Achievement`. Т.е. слой i18n — мёртвый код, `state.language` ни на что не влияет. Переводы, сделанные ранее, в проекте не сохранились.
   Фикс: заново сгенерировать пак `ru`, вызвать `registerContentPack("ru", ruPack)` при старте и прогнать весь контент и UI-строки через локализацию.

3. **Прогресс не синхронизируется с аккаунтом** — таблица `user_progress` создана и защищена RLS, но в приложении используется только в `account.functions.ts:11` (удаление). `ProgressProvider` работает исключительно с localStorage. Итог: вход с другого устройства = пустой прогресс; обещанная миграция/слияние при первом входе отсутствует.
   Фикс: при наличии сессии — загрузка облачного прогресса, merge (max XP, объединение lessons/achievements/favorites, max streak, никогда не перетирать пустыми данными), debounce-запись.

## High

4. **Три готовые админ-панели недоступны** — `SettingsPanel.tsx`, `ContentPanel.tsx`, `LevelsPanel.tsx` нигде не импортируются; `_authenticated/admin.tsx` рендерит только статистику + уроки. Настройки сайта, блоки контента и уровни редактировать невозможно, хотя схема и RLS есть. Фикс: добавить вкладки в `/admin`.

5. **Настройки сайта не влияют на публичный сайт** — `src/lib/site-content.ts` (`useSiteSettings`, `useContentBlocks`, `useLessonSources`) не импортируется ни одним публичным маршрутом. Заголовок, описание, соцссылки, логотип, GA ID из админки нигде не применяются. Фикс: подключить настройки в `__root.tsx`/`AppShell`/`Guide`.

6. **Смена пароля обманывает пользователя** — `_authenticated/settings.tsx:69-73` передаёт `current_password` в `supabase.auth.updateUser` через `as any`; такого параметра в SDK нет, старый пароль не проверяется. Фикс: убрать поле или реально верифицировать (повторный `signInWithPassword`) перед сменой.

7. **Обход блокировки уроков** — `library.tsx:57-68` ссылается на любой урок без проверки `isUnlocked`, а `learn.$lessonId.tsx` не проверяет доступ перед `completeLesson`. Можно пройти любой урок и набрать XP в обход пути. Фикс: проверка `isUnlocked` в Library и на странице урока.

8. **Google-вход отсутствует** — во всём проекте нет `signInWithOAuth`; `/auth` только email+пароль, хотя вход через Google был в требованиях и по умолчанию ожидается.

9. **Нет ссылки «Забыли пароль?» на `/auth`** — `resetPasswordForEmail` вызывается только из `settings.tsx:86-94`, т.е. уже после входа. Заблокированный пользователь восстановиться не может.

10. **`/reset-password` может «зависнуть»** — `reset-password.tsx:30-32` один раз читает `getSession()`; сессия из recovery-ссылки часто появляется позже, подписки `onAuthStateChange` нет → показывается «откройте страницу из письма». Фикс: подписка на `PASSWORD_RECOVERY`/`onAuthStateChange`.

## Medium

11. **Streak считается по UTC** — `progress.tsx:58` `toISOString().slice(0,10)`. Для UZ (UTC+5) занятие после 19:00 засчитывается «завтрашним днём»: серии рвутся или удваиваются. Фикс: локальная дата.
12. **Ложное «+XP» при повторном прохождении** — `completeLesson` возвращает полный `xpGained`, хотя при `already` начисляется 0 (`progress.tsx:145,157,165`); урок показывает «+30 XP», а счётчик не меняется. Плюс `xpGained` мутируется внутри updater-функции `setState` (небезопасно в StrictMode).
13. **XP может уйти в минус** — `toggleChallenge` (`progress.tsx:172`) даёт `-15` без нижней границы; `rankFor` тогда возвращает отрицательный `percent`, который подставляется в `width: %` на дашборде и главной. Фикс: `Math.max(0, …)` и clamp прогресс-бара.
14. **Мигание «нулевого» прогресса** — флаг `ready` из `ProgressProvider` не используется ни одним экраном: при каждой загрузке в шапке кратко видно 0 XP / 🔥0 / Beginner. Фикс: скелетоны до гидратации.
15. **Мигание светлой темы** — `theme.tsx` вешает класс `dark` только в `useEffect`, блокирующего скрипта в `RootShell` (`__root.tsx:123`) нет. Тёмная тема мигает белым при каждой загрузке.
16. **`quiz_attempt` = завершению урока** — `learn.$lessonId.tsx:65-66` шлёт оба события одновременно; метрика «попытки квиза» не несёт отдельного смысла.
17. **Первый зарегистрированный = админ** (`handle_new_user`): проверка «нет строки с ролью admin», а не «нет пользователей». Если единственный админ удалит аккаунт (`deleteMyAccount` чистит `user_roles`), следующий зарегистрировавшийся получит админку.
18. **`deleteMyAccount` не атомарен** (`account.functions.ts:11-22`): при сбое на середине остаётся auth-пользователь без профиля/ролей. Надёжнее удалять `auth.users` первым (каскады) после чистки аватаров.
19. **Нет состояний ошибок в админке** — `SettingsPanel.tsx:34-60` и `ContentPanel.tsx:34-46` игнорируют `error` → вечное «Loading…»; в `admin.tsx` нет `isError` для статистики и списка уроков.
20. **Симуляторы без валидации** — `simulators.tsx:21` `money()` без проверки `Number.isFinite`; отрицательные/нулевые годы и ставки дают `NaN`/`∞` прямо в UI. В `tools.tsx:21` защита есть — привести к одному виду.
21. **a11y квиза** — варианты ответа (`learn.$lessonId.tsx:213-229`) без `role="radio"`/`aria-checked`; результат проверки без `aria-live`, скринридер его не озвучит.
22. **`ready`-флаг и `language` в состоянии не используются** — мёртвая функциональность, вводит в заблуждение при доработке.

## Low

23. SEO: нет `canonical`, `og:url`, `og:image`, `twitter:title/description` ни на одном маршруте; на гайдах есть FAQ (`Guide.tsx:34-44`), но нет JSON-LD `FAQPage`; нет `sitemap.xml`.
24. `dashboard.tsx` — персональная страница без `noindex` (в `settings.tsx:31` он есть).
25. PWA отсутствует полностью: нет `manifest.webmanifest`, иконок, service worker, `theme-color` (пункт из прошлых требований остался невыполненным).
26. Широкие гранты `INSERT/UPDATE/DELETE … TO authenticated` на `lessons/levels/site_settings/content_blocks/...`; сейчас защищает только RLS — при случайном удалении политики таблицы станут открытыми на запись.
27. RLS на `profiles` не ограничивает колонки: пользователь может переписать себе `profiles.email` (расхождение с `auth.users`).
28. Порча localStorage: `progress.tsx:90-101` не валидирует форму данных (`{"lessons":"oops"}` уронит `stats`).
29. Ошибки записи в localStorage (квота/приватный режим) молча глотаются — пользователь не узнает, что прогресс не сохранился.
30. Линтер БД: одна SECURITY DEFINER-функция доступна authenticated — это `has_role`, ожидаемо и безопасно (можно закрыть как принятый риск).

## Что нужно проверить вручную в браузере

- Регистрация e-mail → выход → повторный вход; сохранился ли прогресс (ожидаемо: нет, п.3).
- «Забыли пароль» с `/auth` (ожидаемо: ссылки нет), затем письмо → `/reset-password` → смена → вход новым паролем.
- Смена пароля в `/settings` с заведомо неверным «текущим паролем» (ожидаемо: пароль всё равно сменится, п.6).
- Вход не-админом → открыть `/admin` (должно быть «You don't have admin access»); попытка записи в `lessons` из консоли — должна отклоняться RLS.
- Прохождение урока: сравнить «+XP» в результате с XP в шапке; пройти тот же урок второй раз.
- Streak: пройти урок вечером в часовом поясе UTC+5 и на следующий день — не порвалась ли серия.
- Открыть заблокированный урок прямой ссылкой из `/library` и завершить его.
- Тёмная тема: включить, обновить страницу — заметить вспышку светлой темы; проверить читаемость на уроках, квизах, калькуляторах, дашборде, профиле, админке.
- Мобильный (iPhone/Android): нижняя навигация, перекрытие футера, длинные названия уровней, селекты страны/языка.
- Симуляторы/калькуляторы: ввод 0 и отрицательных значений, очень больших сумм.
- Админка: сохранение настроек сайта и блоков контента (ожидаемо: вкладок нет, п.4), загрузка изображения, публикация/черновик урока, отображение статистики.
- Загрузка аватара >4 МБ и неподдерживаемого формата; смена имени и обновление страницы.
- Выход из аккаунта на защищённой странице: не остаются ли данные в кэше и не возвращает ли «Назад».
